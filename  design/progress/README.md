# design/progress — 里程碑进度与 agent 交接目录

建立：2026-07-23（用户拍板：按里程碑单文件 markdown 方案；备选"markdown+status.json 双写"与"单一 PROGRESS.md"因双写漏写风险/并行冲突被否）。

## 用途

1. **多 agent 交接**：一个里程碑拆成多个子任务分发给不同 agent（或不同会话的同类 agent）执行时，交换环境事实、中间产物位置、坑与结论。
2. **断点恢复**：异常中断（会话崩溃、机器重启、人工暂停）后，用户或新 agent 能从最近断点继续推进，而不是从头读全部设计文档。

与 ` design/` 根目录文档的分工：

- ` design/` 根：决策记录、验收报告、基线——**长期 canonical**，完成后不再改（除勘误）。
- ` design/progress/`：**操作性状态**，执行期间频繁更新；里程碑收口后归档不再更新。

## 文件命名与生命周期

- 每个里程碑一个文件：`<date>-<milestone-slug>.md`（date = 里程碑立项日）。
- 立项：随任务书一同创建，初始状态全 `pending`。
- 执行：按下方"更新纪律"持续更新。
- 收口：里程碑全部子任务 `done`/`skipped` 后，文件头部状态改为 `已收口`，closeout/验收文档引用本文件；此后不再更新。
- ` design/INDEX.md` 在对应阶段分组中链接进行中的 progress 文件。

## 文件结构模板

```markdown
# <里程碑名称> — 进度与交接

状态：进行中 | 已收口
任务书：<链接>
最近更新：<ISO 时间> by <agent 标识>

## 1. 子任务状态表

| 子任务 | 状态 | 执行 agent | 更新时间 | 产出 |
|---|---|---|---|---|
| N1 ... | pending/in_progress/done/blocked/skipped | | | <commit/文档路径> |

## 2. 交接信息（跨 agent 共享事实）

<环境事实、中间产物路径、坑、互为依赖的结论。每条标注日期与来源 agent。>

## 3. 断点恢复指引

<"如果从零接手：已完成 X，下一步做 Y，验证命令 Z"。每次状态变更后必须保持本节可执行。>
```

## 更新纪律（执行 agent 必须遵守）

1. **认领即写**：开始某子任务前，先把状态改为 `in_progress` 并署名（agent 标识 + 时间），再动手——防止并行 agent 重复认领。
2. **完成即写**：子任务完成后立即填 `done` + 产出（commit hash / 文档路径），并刷新"断点恢复指引"。
3. **中断必写**：主动暂停或被异常打断前（能写就写），状态置 `blocked` 或保持 `in_progress` 并在交接信息里留"断点"条目：做到哪一步、下一条命令是什么、有哪些未提交改动。
4. **随工作提交**：progress 文件的更新与该子任务的工作成果同一 commit 提交（或紧跟的 docs commit），禁止"活干完了进度没写"。
5. **只追加不抹除**：交接信息按时间追加，不删旧条目（过时的标注"已被 X 取代"）。
6. 状态值仅用：`pending` / `in_progress` / `done` / `blocked` / `skipped`。
