# issue-023：裁判 API 余额耗尽 + 无上限指数退避——D7 跑批静默挂起 10 小时

## 现象

- 2026-08-25 22:32（CST）起，D7 四臂跑批停止产出新成绩记录，进程仍存活（PID 93359）。
- 日志 `/tmp/campaign-9b-d7.log` 显示裁判调用持续报 `402 Insufficient Balance`（DeepSeek 账户余额耗尽，经 8899 relay 透传）。
- 裁判重试逻辑：`JUDGE_API_MAX_RETRIES=100`，退避 `5s × 2^(n-1)` **无上限**——第 13 次失败后下次重试等待约 5.7 小时，第 20 次约 30 天，事实上等于永久挂起，且无任何告警通道。
- 最后一个成功出分：x1 task_00085（score=0.00，max_turns，裁判仍正常时产出）。卡住的裁判调用属于其后排队任务（x2/x3 task_00085 之一）。
- 余额耗尽期间**没有写入任何受污染的分数**（402 全部 fail 在裁判调用层，分数未落盘）。

## 影响

- D7 完成 69/96 执行单元后停摆约 10 小时（22:32 → 发现时 08:42）。
- 单线程批处理被一次裁判调用堵死，后续 27 个单元全部排队等待。

## 根因

1. 直接原因：DeepSeek 账户余额耗尽（402）。
2. 结构原因：裁判重试退避 `5×2^n` 无上限封顶，且把 402（账户类不可重试错误）与 5xx/超时（瞬时错误）同等对待，无限重试。
3. 可观测缺口：余额耗尽/裁判连续失败没有任何告警；监视器只看进程存活，看不到"活着但不动"。

## 处置（已做）

- 2026-08-26 08:42 人工发现。已落盘成绩确认干净（402 未污染任何记录）。
- 用户充值 DeepSeek 后，跑批会在下一次重试自动恢复，无需重启、无数据损失。
- 2026-08-26 09:03 用户充值完成并验证可用（direct API 200）；为避免等下次退避重试（约 10:07），重启 campaign（resume 自动跳过 69 个已完成单元），D7 于 16:48 全部跑完（96/96）。

## 待修（D 收口后，不阻塞当前批次）

- [ ] 退避封顶（如 5s×2^n 封顶 10min）+ 402/401/403 账户类错误快速失败并响亮告警
- [ ] 裁判连续失败 N 次 → 写哨兵文件/非零退出，让监视器能发现"活着但不动"
- [ ] preflight 加余额检查项（DeepSeek 余额 API 查询，余额 < 阈值直接拦下不开跑）
- [ ] 监视器巡检增加 run.jsonl mtime 停滞检测（如 >30min 无新行即告警）
