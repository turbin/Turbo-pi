# 方案：库版本交叉评估臂（演进方案 6，2026-08-14 用户裁决立项）

- 状态：**已立项（用户 2026-08-14 裁决 4）；与 9B 全量重跑批合并排期**
- 来源：概要设计 v2 §5 演进方案 6；08-13 对抗式审查乙-F2（库演进效应与即时注入效应未分离）
- 预估：harness 改造 0.5-1 天人工工时；跑批日历时间并入 9B campaign（每增一臂每日 +20 任务，9B 单机测速后报价）

## 问题

C 阶段的 +10.3pp 对照增益是两种效应的混合体：

1. **库演进效应**：经验库多日积累（卡片数量/质量随夜间进化增长）带来的行为变化
2. **即时注入效应**：当天检索注入的卡片对当天行为的影响

现有双臂设计（实验臂=当日库+注入开 / 对照臂=注入关）无法把二者拆开——"记忆有用"的归因粒度停留在混合体上。9B 重跑批是重做的窗口期，交叉臂应在起跑前内建，否则 9B 数据将继承同样的归因模糊。

## 设计：库版本 × 注入开关 2×2 交叉臂

在 9B 重跑批重复集（每日同 20 任务）上跑四臂：

| 臂 | 库 | 注入 | 测量对象 |
|---|---|---|---|
| X1 | 冻结 D1 快照库 | 开 | 固定库的即时注入效应（无演进混淆） |
| X2 | 当日库 | 开 | 演进+即时混合（= 原实验臂口径） |
| X3 | 当日库 | 关 | 无注入对照（= 原对照臂口径，抗漂移参照） |
| X4 | 冻结 D1 快照库 | 关 | 纯 9B 重复测量基线（漂移地板） |

差分口径（预注册）：

- **库演进效应** = X2 − X1（同注入开，库版本差）
- **即时注入效应** = X1 − X4（同冻结库，注入开关差）
- ** sanity 臂差** = X3 − X4（学习回路对无注入行为的间接影响，预期 ≈0；显著非零则说明有未建模混淆）
- C 阶段 +10.3pp 的对应量 = (X2 − X3) − 漂移修正，可拆为 库演进 + 即时 两部分之和

## 实施改动点

1. 检索侧指定库版本：评估实例支持加载指定快照（snapshot_store 已有冻结副本机制，M10）；冻结臂锁 D1 快照全程不换载
2. campaign.py 臂配置扩展为四臂（现仅 experiment/control 两臂，`campaign.py:224` 附近）
3. 每臂 request 全量落库（F0 修复后的口径），分数差分离线计算
4. 预注册：差分口径、n=20 功效声明（红线 6，小样本不报显著性）、判据阈值

## 顺序约束（用户 08-14 新增实验顺序决策点）

先在 **QwenClawBench 一类 office 案例集**跑通四臂 → 向用户报告测试结论 → **用户确认后才进入 ALFWorld** 域测试。ALFWorld 臂的库与任务集届时另报。

## 验收

- 四臂数据完整落库，差分口径可复算
- 库演进效应与即时注入效应分别定量报告（含功效声明）
- sanity 臂差检验通过或对非零结果给出解释
