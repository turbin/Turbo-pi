# D 阶段后续实验流程重设计

日期：2026-08-27 ｜ 状态：**V1 定稿（5 轮 Kimi 工程调查 × Codex 批判审查完成；待用户批准实施）**

上游：`2026-08-27-9b-campaign-d-phase-final-report.md`、`issue-019`、`issue-020`、`issue-021`、`issue-023`、`issue-024`

## 1. 要回答的问题

后续实验不再把“继续扩充记忆库”当成默认动作，而按顺序回答五个问题：

1. D7/T9 的差异是否来自不独立工作区、实例、wrapper 或其他未控制条件？
2. 注入路径本身、注入剂量和卡片内容，分别贡献了多少收益或伤害？
3. 记忆 v2 能否在未见任务上提供稳定收益，同时降低灾难性失败？
4. 任务级门控能否识别失败，并以可接受的误报率和成本升级？
5. 通过办公任务验证的机制，是否值得带入 ALFWorld？

## 2. 总体流程与冻结纪律

```text
证据与确认集冻结
→ P0 实验基础设施与 issue-023
→ E0 测量系统与臂等价性审计
→ E1 注入路径/剂量安慰剂实验
→ 按结果分支：停止 / E2 卡片质量闸 / E3 记忆 v2 组件筛选
→ E5a 任务级 shadow detector 开发并冻结
→ E4 功效充分的跨日确认实验 + E5b 前瞻 shadow 验证
→ Go/No-Go 裁决
→ 通过后进入 ALFWorld
```

统一纪律：

- E0–E5 期间冻结 D7 原始库、运行结果和原始评分，不回写、不补行、不重新进化。
- 每个实验开始前按 `2026-08-19-run-batch-preflight-checklist.md` 全项核验；探针必须看真实响应。
- 每次运行使用全新工作区；不得用 `dirs_exist_ok=True` 合并到上一次运行目录。
- 每个实验冻结并记录代码 commit、模型指纹、**实际生效且可观测**的采样参数、实例、库文件 SHA256、完整增强提示词 SHA256、注入卡 ID/顺序、任务顺序、judge 指纹、trace ID、终止原因和双评分。采样合同采用“支持矩阵”：显式固定链路支持的 `temperature=0` 与 `max_tokens`；不支持或不可观测的 `seed/top_p` 标为 unsupported，并保证所有臂使用同一 provider 默认值，不能伪填为已控制。
- 不把开发调试样本计入正式检验；正式结果目录在启动前必须不存在。
- 主指标、样本量、排除规则、停止规则和检验族在开跑前写入机器可读 manifest；结果出来后不得修改。
- `score_simple` 与 penalized score 同报；均值收益和尾部风险分开裁决。
- 立即从实际 `run.jsonl` 生成任务暴露清单并冻结：已进 evolution、已执行但未进 evolution、从未执行三类不得混称。当前实测仍有 20/99 个任务从未执行；这 20 题在 E4 前禁止用于开发、E0–E3、提示调优或人工查看答案。

## 3. P0 + E0：基础设施与臂等价性审计（硬前置）

在任何需要 judge 的真实运行前，先完成 issue-023 的 401/402/403 快速失败、退避封顶、余额探针与停滞告警；否则 E0 本身也可能再次挂死。

### E0.1 T9-R2 独立重跑

- 修复 `rerun_audit.py`：每个任务、每次重复使用独立的 `repeat-N/<task-id>` 工作区；开始前断言目录不存在。
- `rerun_audit.py` 只负责独立重复，不承载任意注入内容覆盖；内容/path 探针使用单独的 eval-only harness，避免把诊断接口混进通用重跑器。
- 原预注册 5 题 × 3 次保留用于可追溯复核；另将 `task_00002`、`task_00060`、`task_00065` 作为定向机制探针单列，不与原 5 题汇总。
- 每次保存 transcript、产物清单/哈希、执行元数据和评分拆分；诊断轨迹写入隔离目录，禁止进入 evolution。
- 不再把 5 题平均极差称为“全局噪声 floor”；报告任务级分布、最大极差和置信区间。

### E0.2 臂条件指纹

对 current/frozen 实例分别发送同一条固定请求，逐项比较：

- 原始 system/user/tool 输入；
- 检索前 query；
- retrieved IDs/scores/order；
- injection wrapper 与完整增强 prompt；
- 模型、temperature/top-p/seed/max_tokens；
- workspace 初始文件树哈希；
- gateway 与 agent-server 配置指纹。

当前链路只部分透传采样参数，且 `request_traces/model_runs` 不保存完整采样配置。因此 P0 必须增加 canonical request hash、支持参数的落盘字段及回归测试；无法固定的参数按支持矩阵标为“不支持”，不得声称已控制。除预注册变量外任一指纹不一致，E0 失败，后续因果实验不得启动。

### E0.3 注入开关等价性探针

新增独立的 eval-only `injection_probe`，在同一实例、同一冻结库、同一全新工作区下比较五种请求。现有 `injection` 布尔值不足以构造这些条件，必须先增加显式的评估覆盖接口，并保证生产请求默认不可调用：

| 臂 | 条件 | 目的 |
|---|---|---|
| P0 | injection off | 裸基线 |
| P1 | wrapper on + 空 experience + Skill/SOP 全关 | 只测 wrapper/代码路径 |
| P2 | wrapper on + Skill/SOP on + 空 experience | 测非卡片注入通道 |
| P3 | wrapper on + 等长中性文本 + Skill/SOP 状态固定 | 测上下文剂量/注意力占用 |
| P4 | wrapper on + 固定真实卡片 + Skill/SOP 状态固定 | 测内容效应 |

先用 8–10 个已暴露哨兵任务做机制探针；该阶段只判断路径是否等价，不宣告总体收益。`injected_tokens` 当前只是字符数除以 4 的启发式估计，剂量匹配必须使用目标 tokenizer 或 gateway 的真实 prompt token 差值。

**E0 通过条件**：独立工作区成立；P0/P1 发往 gateway 的 canonical system/user/tools/request 除 condition label 外逐字节相等；实例/臂指纹除预注册变量外一致；`task_00002` 在干净条件下完成定向复跑并归档为“复现/未复现/证据不足”，不强迫给出单一根因。8–10 题不用于统计“行为等价”；机械等价不过就先修 harness，不进入 E1。

## 4. E1：注入路径与剂量实验

在 E0 通过后，使用同一实例和冻结库，采用任务内配对、臂序随机。设计为“裸基线 + 2×2（内容 × 剂量）”：

- D0：不注入；
- D1：低剂量中性文本，逐任务匹配真实 top-2 的 token 数；
- D2：低剂量真实 v1 内容，top-2；
- D3：高剂量中性文本，逐任务匹配真实 top-8 的 token 数；
- D4：高剂量真实 v1 内容，top-8。

中性文本模板在开跑前冻结，必须语义惰性且不得含任务提示。核心 estimand：D2−D1、D4−D3 为内容效应；D3−D1 为纯剂量效应；两者差分为内容×剂量交互。D0 只衡量完整注入路径相对裸基线的产品效应，不与上述组件效应混称。

### E1 后的预注册分支

- wrapper/机械路径在 E0 致害：修复后重跑 E0，不启动 E1。
- 中性高剂量 D3 明显致害：先治理 wrapper、位置或剂量，再决定是否做最小 E3；不能归因给卡片。
- 真实内容 D2/D4 劣于等剂量中性臂：E2 内容治理和相应 E3 为必做。
- 真实内容既无伤害也无实用收益：可直接 No-Go 记忆并停止；只有用户仍要战略性探索 v2 时才进入 E2/E3。
- 低剂量受益、高剂量致害：优先选择剂量门，E3 只验证最小候选，不默认跑全五臂。

## 5. E2：卡片分类与离线质量闸

### 样本与标注

- 从 906 张 active 卡中按类型、质量分、复用次数、来源任务和是否进入 D7 注入进行分层抽样。
- 第一阶段标注 120 张，必须覆盖全部 D7 实际注入卡、高复用/高风险卡，并保留按来源和类型随机覆盖；只有稀有类别置信区间或一致性不足时才扩至 200，仍不足再扩至 500。
- 两名独立标注者 + 一名裁决者；报告 Cohen's kappa、类别一致率及不确定项。
- 冻结类别：自言自语、任务特定攻略、程序性片段、可迁移方法、边界/Guard、其他。
- 标注先保存在版本化 sidecar（`card_id`、标签、标注者、理由、规则版本、裁决结果），不直接扩充或改写生产 `experiences` schema；只有验证为有效的标签才考虑进入运行时字段。

### 质量闸

- 自言自语和无完整语义的程序性片段拒收。
- procedure 必须与源任务交付规范逐项对齐，不得创造额外交付物、路径或文件名。
- 卡片必须声明适用条件、禁止条件、来源任务和可迁移范围。
- 教师/verifier 不能只凭语言流畅度放行；必须检查可执行性、交付一致性和跨任务适用性。

交付对齐不能信任卡片自报：先从源任务正文、grader 规则与人工裁决生成版本化 `deliverable_manifest`，带任务文件 SHA256；再将卡片 `procedure/deliverables` 与该 manifest 比较。无法自动确定的任务进入人工裁决，不允许模型自行补齐官方要求。

先用现存卡片做离线 precision/recall 校准，再冻结规则。若 E2 显示教师生成是主要错误来源，issue-020 三教师对照也只能放在规则冻结之后，避免比较三位老师在错误 schema 下谁更会写“漂亮废话”。

## 6. E3：记忆 v2 组件筛选

完整候选五臂如下，用于回答 wrapper 与内容闸的独立贡献：

| 臂 | 卡片 | wrapper |
|---|---|---|
| S0 | 无 | 无 |
| S1 | v1 原库 | 原 wrapper |
| S2 | v1 原库 | 新 wrapper（原任务/交付优先，卡片仅参考） |
| S3 | v2 过滤库 | 原 wrapper |
| S4 | v2 过滤库 | 新 wrapper |

S1–S4 固定 top-k 和真实 token 剂量；不足部分用中性 padding 而不是增加别的卡。S0 保持真正裸基线，不做 padding；因此 S4−S0 衡量完整产品效应，而 S2−S1、S3−S1 等固定剂量对比衡量组件效应，二者不得混称。先从**已经执行过**的任务中选 20 个诊断任务筛选，严禁使用为 E4 封存的 20 个从未执行任务。结果只用于选定 v2 组合，不作为最终上线证据。

v2 库必须由只读 v1 快照通过可复现 builder 派生：输入快照 SHA256 + sidecar 规则版本 → 输出新 SQLite + manifest + SHA256。禁止手工改库或修改 live DB；被过滤卡只在派生库中标为 removed/dormant。

主要对比：S4−S0（整体价值）、S4−S1（修法价值）、S2−S1（wrapper）、S3−S1（内容闸）。使用 Holm 校正；未列出的比较标记为探索性。是否跑完整五臂在 E1 结果落盘后、查看 E3 结果前预注册：只出现剂量问题时允许裁剪为裸基线/旧方案/限剂量方案；真实内容致害时必须保留等剂量内容闸对照。

## 7. E4：跨日确认实验

只保留三个臂：

- C0：无记忆；
- C1：冻结 v1 原方案；
- C2：冻结 v2 候选方案。

### 任务与运行

- 至少两个独立 block 日；每天每个任务三个臂都跑，臂序按 task-block 随机。
- 严格确认集首先使用实际 `run.jsonl` 未出现过的 20 个 QCB 任务；任务 ID 清单及其任务文件 SHA256 在任何实现/调参前冻结。原 8 个 held-out 已在 D7 执行，只能作为“未进入 evolution”的次级外部验证，不能再称为“从未执行”。
- 生成机器可读 `confirm-task-manifest.json`；所有 E0–E3 runner 加 denylist，发现确认集 ID 立即失败。设计/标注阶段只允许读取 ID 与哈希，不读取确认集正文；E4 runner 只有显式加载冻结 manifest 才可运行这些任务。
- 两个 block 日重复同一任务只增加运行重复数，不增加独立任务数；统计功效的独立样本单位仍是任务。若 20 个严格新任务不足以达到预注册功效，必须引入新的 office 任务集，不能用跨日重复伪装成 n=40。
- 同一 block 内库和代码完全冻结，不做夜间 evolution。
- 样本量由最小重要差异决定：平均分最低实用收益、平均分非劣界、FunctionalSuccess 非劣界和灾难率安全界是四个不同参数，不得混用。先用**不含确认集**的诊断任务得到配对差分/discordant-pair 分布，再计算功效；不得直接照搬 D7 总体 sd。暂定业务门为平均分点估计至少 +0.05、灾难率不高于 C0 +5pp 且绝对不高于 10%，最终统计界在 power 脚本和用户批准后冻结。

### 预注册主指标与检验层级

1. 共同主效用：C2−C0 的 paired `score_simple`，单侧 95% CI 下界高于 0，且点估计至少 +0.05；
2. 共同主安全：C2−C0 灾难性失败率差的单侧 95% CI 上界不超过 +5pp，且 C2 绝对灾难率不超过 10%；
3. 关键次指标：FunctionalSuccess 非劣，暂定界 −5pp；EfficientSuccess、penalized score、token、回合、墙钟与云升级成本；
4. C2−C1 及分层/日期分析属于次级检验族，使用 Holm 校正；不得用其中某一显著项替代共同主指标。

正式样本量必须同时满足效用和安全两个共同主指标的功效要求。若 20 个独立任务不足，选择“补充新的外部任务并重新冻结”或“No-Go/证据不足”，不得靠重复日期补足。

### Go/No-Go

C2 只有同时满足以下条件才可进入 ALFWorld：

- 对 C0 的平均效用点估计至少 +0.05，且单侧 95% CI 下界高于 0；
- 灾难性失败率不高于 C0 的预注册安全界；
- FunctionalSuccess 通过预注册的非劣检验；
- 结果在两个 block 日方向一致；
- held-out/new-task 子集不存在明显负迁移；
- 数据完整性、泄漏和 treatment compliance 全部通过。

“p>0.05”不能当作非劣证据；必须使用预注册非劣检验或置信区间。

## 8. E5：任务级门控 shadow 验证

issue-019 先只做 shadow，不改变 C2 主实验路由。任务级 gate 不放进现有 gateway `quality.py`：该层按合同只看单请求响应，无法观察跨回合进展。shadow detector 先作为轨迹级离线组件，真正在线介入以后再放到 agent/harness 层。候选信号包括：连续工具失败、重复命令/状态无进展、临近 MAX_TURNS、必需交付物缺失。

E5 分为两个时序阶段：E5a 在 E4 前完成 detector 开发与阈值冻结；E5b 只随 E4 做前瞻 shadow 计分，不再调规则。数据切分为 D1–D6 轨迹开发、D7 冻结前验证、E4 严格新任务前瞻测试。必须按 task 切分，不能把同一任务的不同臂/日期拆到训练和测试两侧。

报告任务级 TP/FP/TN/FN、召回率、精确率、误报率、**在 80% 回合预算前的及时召回率**、触发时点、预计云成本和 DLP 阻断比例。启用线上升级前另做独立干预测试；不得用同一批轨迹同时调阈值和报最终性能。

任务级升级若需要发送累计状态，只允许发送最小化、结构化、已脱敏的任务摘要，不默认上传完整 transcript 或 workspace 内容；现有 request-envelope DLP 继续作为最后一道阻断，但必须增加按 task/run/arm 的 finding 计数，才能核算敏感内容风险。

issue-023 的 401/402/403 快速失败、退避封顶、余额预检和停滞告警是所有新跑批的工程前置，不与记忆效果混在同一因果变量中。QCB `lib_grading.py` 位于工程内但整个 `eval/qcb/` 被 gitignore；修复不得只改该参考副本，必须在受版本控制的本地 judge adapter/runner 层实现并测试。

gateway 已有 `model_runs.cost_micro_usd`，但现有汇总是全库范围、不能按本次实验可靠过滤。E5 必须通过 trace→task/run/arm 关联计算升级成本，不重复发明成本字段。

`request_traces` 必须增加或可靠关联 `arm/block/condition`；当前仅按 task_id 对账会把同任务不同臂的注入 trace 混在一起，不能用于 E1/E3/E4 的 TreatmentCompliance。

## 9. issue-020 / issue-021 的排期

- issue-020（三教师）：仅当 E2 显示错误与教师生成有关且 schema/质量闸已冻结时再跑；决定教师选型，不代替学生效用实验，也不是主线自动步骤。
- issue-021（plan-to-file）：与记忆主实验分开。先在无记忆条件做 S0/S1 脚手架 A/B，确认不挤占交付后，才研究与 v2 的交互；ST MCP 另批。

## 10. 停止规则

- 任一臂条件指纹越界、工作区残留、库热更新、评分链路切换或关键 trace 缺失：立即停批，当前 block 作废。
- 发现明确安全伤害且达到预注册停止界：停止该臂，不以“补样本”继续暴露。
- judge 不可用或余额不足：失败退出，不写 0 分，不无限等待。
- 不允许根据中途均值改样本量；若采用序贯设计，边界必须事前冻结。

## 12. 最小可行实施路径

```text
P0（confirm denylist、独立 workspace、arm/condition trace、canonical request hash、issue-023）
→ E0（机械臂等价 + T9-R2）
→ E1（裸基线 + 内容×剂量）
→ 按预注册分支停止或进入 E2/E3
→ E5a 冻结 detector
→ E4 + E5b 前瞻 shadow
→ 共同主指标裁决
```

下一授权点不是“全流程一次开跑”，而是仅批准 **P0 + E0 实施包**；E0 验收通过后再单独批准 E1。
