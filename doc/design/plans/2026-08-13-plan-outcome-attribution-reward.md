# 方案：经验卡实战结果归因奖惩机制（记忆版 Fisher 分数 + 置信度）

- 状态：**待启动（C 阶段完成后询问用户确认）**
- 来源：issue-010 修复项 5 + issue-012 评审采纳项 1/7（用户 08-13 确认）
- 预估：1-2 天

## 问题

卡片质量分 = 裁判自评，与真实执行结果脱钩（issue-010 结构性根源）；行为层无奖惩——卡误导了执行，系统无从知晓。

## 方案

1. **归因数据管道**：request_traces.retrievedIds × 任务分数 join →「卡 × 结果」关联表（数据均已落库，纯离线计算）
2. **奖惩规则**：
   - 奖励：被注入且任务高分的卡 → quality 微调加分（上限封顶）
   - 惩罚：被注入且任务重复失败的卡 → 降分 / 降 dormant / 强制重验
   - **最小样本阈值**（如 ≥5 次注入才允许奖惩动作，防小样本误杀）
   - **对照校准**：用对照臂（injection off）同任务分数做差值，区分"卡的作用"与"任务本身难"
3. **置信度元数据**：quality 扩展为 (quality, confidence/样本数) 二元组；新卡低置信起步，随实战证据累积；高确信+低样本卡在检索排序中降权
4. **复用现有管道**：rescore 管线/demote 机制不动，本方案只是新增一个信号源
5. **回归测试**：合成「卡 A 注入后任务连续失败」序列 → 断言 A 被降权/降级；「卡 B 注入后连续成功」→ 断言加分；小样本（<阈值）不动

## 明确不做

- token 级 RL / 权重更新（与本地 4-bit 部署形态不兼容）
- 单请求级即时奖惩（噪声太大，按日批次离线结算）

## 验收

- 对 C campaign 历史数据回放：该机制能否自动标出 issue-010 中导致降分的卡（后验验证）
- 全部测试绿
