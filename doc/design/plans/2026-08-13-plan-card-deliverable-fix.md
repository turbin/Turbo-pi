# 方案：经验卡交付物维度修复（issue-010 主体）

- 状态：**待启动（C 阶段完成后询问用户确认）**
- 来源：issue-010（照卡执行挤占交付本能）；登记 2026-08-12
- 预估：1-1.5 天（含存量卡重蒸馏 ~1.5h 管线运行）

## 问题

重复集分数 D1 0.567 → D4 0.378（D5 回升 0.467）：Method 卡只含过程步骤、缺交付物要求，模型照卡完成分析但不写交付文件（task_00091 实证：分析获 judge 认可但 output_file_exists=0）。

## 方案

1. **蒸馏模板加交付物维度**：卡片 schema 增加 `deliverables` 字段（任务交付物清单：文件/产物/状态），蒸馏 prompt 要求显式提取"任务最终必须产出什么"
2. **验证闸门加交付检查**：回放验证增加必要条件——按卡执行的轨迹必须产出交付物（无交付轨迹 → 质量分封顶 <0.5，物理拦截）
3. **存量卡重蒸馏**：现役 C 库卡片用新模板重蒸（或批量补 deliverables 字段）
4. **回归测试**：构造"分析完整但无交付"合成轨迹，断言闸门拦截；卡片 schema 校验测试

## 验收

- 修复后短程验证 campaign（重复集 3 天）分数曲线不低于无注入基线
- 全部测试绿 + npm run check 干净
