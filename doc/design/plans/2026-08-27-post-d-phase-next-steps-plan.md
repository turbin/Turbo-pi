## 前置事实（D 阶段终审结论）

1. 记忆系统按当前形态（只攒不管 + bm25 检索 + 强遵循注入）**无正增益**；D7 主检验 −0.177、p=0.0425 卡边，剔除 3 极端任务后 −0.072、p=0.309 不显著。可确证结论：**无正增益 + 少数任务灾难性脱轨风险**，不能推断"平均净负效应"。
2. 致害机制有个案级硬证据：攻略卡/注入计划拉偏交付遵循（task_00065 单卡换入自然实验 + Oracle task_00060 同构）。碎碎念卡、9B 执行方差为风险因子/放大器，致害率未知。
3. 库质量失灵：碎碎念卡（41~110 张，识别规则未固化）高分高复用；同源多卡率 96.4% 是设计同义反复，不度量内容重复度。
4. 工程面：零泄漏、Compliance 28/28、双裁判审计同日一致通过。**零升级≠健康**：全 363 行请求级 MissedEscalationRate=100%（FN=211），任务级亦 100%（FN=49），门控对任务级失败完全失明。

## 方案选项

### 方案 A：先修记忆系统再进 ALFWorld（推荐）

**理由**：带着已证伪的记忆形态进新场景，ALFWorld 结果不可解释（分不清是场景难还是记忆害）。修法清单（issue-024）全部落地后再开新场景，新场景实验才有判别力。

内容（按依赖排序）：

1. **T9 补做扩展审计**：当前 5×3 结果只能说明这 5 题在当前配置下同条件稳定；需补做 temperature=0 vs >0、跨实例、跨 workspace、≥20 任务扩展样本，才能判定 0.0067 是随机噪声 floor 还是确定性伪影。预计 0.5–1 天（受本地 9B 推理耗时约束）。
2. **记忆系统 v2 设计**（设计稿先行，用户批准后实施）：
   - 蒸馏质量闸 + 卡片类别消融：先固化碎碎念/攻略卡/程序性片段识别规则，人工标注 200–500 张，做"仅移除某类卡"注入实验；issue-020 三教师对照仅作为**教师选型输入**，不是内容闸本身。
   - SOP 卡交付物对齐校验：升级为"procedure 与源任务交付规范对齐"。
   - 注入 wrapper 措辞治理（Oracle-C 实证）。
   - 注入侧指令层：交付物第一优先，卡片仅为参考。
   - 检索/注入侧防御层：retrieval confidence gating、top-k 剂量控制、注入前 verifier。
   - 评分罚则双口径日常核算。
   - 存量碎碎念卡处置：先冻结新增，再分批移除（需用户二次确认）。
3. **记忆系统 v2 验证（重写为功效驱动设计）**：
   - **功效分析**：以 D7 观察到的 sd≈0.365 为参照，n=20 对 −0.177 效应的功效仅约 0.59，对 −0.072（drop-3）仅约 0.16；目标功效 0.80 需 n≈40（−0.177）或 n≈120（−0.072）。尾部零分率检测：若目标零分率为 10%，n=20 检出概率 0.88，n=40 达 0.985。
   - **跨日 block**：至少 2 个四臂日（D-day 与 D+1-day），每日内部 task-block 随机化，冻结库臂挂双实例，以分离 ±0.07 日漂移。
   - **虚拟臂**：增加"仅检索不开关"（固定检索 top-k 但 injection=false）与"固定检索内容 + injection=on"臂，分离"库内容"vs"检索/注入实现"。
   - **成功/失败判定**：主检验 X2−X1 >0（或至少非负）且零分率 ≤10%；任一未满足则继续迭代 v2。
   时间：设计稿 0.5 天 + 实施 2–3 天 + 复验 2–3 天（含跨日 block）。
4. **基础设施硬前置**：
   - issue-019 任务级门控改造（ALFWorld 硬性前置，否则 0% 升级无法检测失败）。
   - issue-023 裁判退避封顶+余额检查（纳入本批次，与记忆 v2 解耦）。
5. 通过后才进 **ALFWorld**。

### 方案 B：记忆冻结，直接进 ALFWorld

**技术冻结配置**：
- 经验库切换为只读（`experience.status` 不更新），或 `injection=false` 全关；
- 仍走本地 omlx 9B + 请求级门控，但不注入任何 memory；
- ALFWorld 目标改为"9B 基线 + 任务级门控（issue-019 改造后）能否在新场景自治"。

**能回答的问题**：ALFWorld 下 9B 裸跑或零记忆跑的成功率、门控升级率、任务级失败召回率。
**不能回答的问题**：memory 对 ALFWorld 是益是害；v2 修法是否有效；教师/检索/注入机制在新场景的因果效应。
**机会成本**：若后续仍需验证 memory，则必须在 ALFWorld 后再开一轮"记忆 on/off"对照，整体周期不会缩短，只是把记忆验证推后。
**适用条件**：用户明确把"ALFWorld 场景里程碑"优先级置于"记忆系统可解释性"之上。

### 方案 C：先清 deferred 债再定方向

**内容**：并行完成 issue-019（门控任务级改造）、issue-020（三教师蒸馏对照）、issue-021（推理脚手架 2×2）、issue-023（裁判退避封顶+余额检查），再用结果反推记忆 v2 设计参数。
**时间**：约 5–7 天（issue-019 设计+shadow 回放、issue-020 蒸馏+学生效用注入、issue-021 两因素实验）。
**信息产出**：
- issue-019：任务级 gate 的 TP/FP/TN/FN、召回率、误报率；
- issue-020：哪位教师蒸馏出的卡质量更高、学生注入效用是否 >0.05；
- issue-021：推理脚手架对 9B 能力瓶颈的真实改善幅度。
**风险**：周期最长，可能延迟 ALFWorld；但 v2 设计参数更扎实，减少返工。
