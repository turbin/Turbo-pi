原方案结论：No-Go。资深 AI 架构师与资深 Agent/后端工程师独立审阅后认为，原稿不能直接开工。完成本页 P0 修订与真实兼容探针后，项目状态转为 Conditional Go。

完整问题、后果、修订建议和验收方法见独立的 Agent Team 审阅报告。Markdown 设计稿是唯一规范源，本 HTML 是同步展示稿。

1. 目标与边界

Agent Gateway 是模型网关，不是新的 Agent Client。窄 V1 负责本地优先、确定性云端升级和可恢复的 request trace；自然语言反馈分类与规则学习在核心通路稳定后进入 V1.1。

  • 本地优先 先调用 omlx 的 gemma-4-12b-it-4bit。
  • 确定性升级 本地输出命中可观测硬门时，最多转发一个已配置云 provider 一次。
  • 延期学习 显式反馈、独立 verification 和规则候选保留接口，但不进入第一周。
  • 本地验证 Gateway、LobsterAI、omlx 先全部运行在同一台 Mac mini。
第一版不做：不承诺任务级 trace，不按时间窗口归因满意度，不依赖模型自报置信度，不做双云 fallback、规则抽取、分布式组件、小模型微调，也不让外部 memory 绕过规则审批直接进入 system context。

2. 论文机制与工程落地

本设计分别借鉴 SkillDisCo 的“跨成功轨迹提炼可验证过程知识”和 MAGE 的“以执行状态而非语义相似度管理记忆”。两者均是架构假设来源，不是本项目的性能承诺。

机制论文中的做法本系统的受控落地
SkillDisCo：归一化与子目标将成功 trace 表示为明确控制流，抽取多步骤子目标，并从多个成功实例中寻找共享过程。只产生脱敏 LearningPacket 与受限规则候选；单条 trace 不能直接成为规则。
SkillDisCo：规格与验证给技能定义输入、前后置条件、副作用，再用留出样本验证可执行实现。使用 rule lint、冲突检测、正反 fake fixture 回放和人工审批；产物是文本 RuleVersion，不是可执行技能。
MAGE：两层状态树底层保存 action-observation，顶层按子目标压缩摘要；当前状态来自根到当前节点的路径。V1.2 后仅建立只读派生状态索引，用于离线诊断与候选发现，不能改变在线 trace 查询、prompt 或路由。
MAGE：Grow / Compress / Maintain / Revise追加轨迹、边界压缩、验证摘要、从错误边界分支重试。映射为离线摘要、verification/evaluator、FailureCase 和隔离分支；绝不自动回滚用户工作区或重跑模型请求。
三层隔离：V1 在线请求层只使用已批准规则；V1.1 学习层只处理脱敏、已验证的摘要；V1.2 研究层只能提出候选，不能自动执行工具、修改权重或改变路由。

6. 路由与质量门控

  1. 认证 API key，得到唯一的 client_id / workspace_id / channel_id。
  2. 为一次 HTTP 请求创建 request trace，进行幂等占位并进入有界公平队列。
  3. 调用 omlx，并检查响应结构、空输出、length、tool arguments、forced tool、DLP 与独立 verification。
  4. 硬门通过则接受；确定性失败且满足出云授权/DLP/预算时，调用选定云 provider 一次。
  5. 通过 lease/version 状态机记录结果，再以普通 JSON 或 heartbeat + 最终 SSE 返回。
escalation_score =
  3 * patch_or_schema_invalid + 3 * high_risk_action
+ 2 * verification_failed     + 2 * cross_module_or_multi_file
+ 2 * context_insufficient    + 1 * local_model_low_confidence
+ 1 * recent_similar_failure  + 1 * user_negative_signal

上述启发式分数保留为 shadow telemetry，只用于建立评测集；在证明误接受率和升级召回率之前，不改变生产答案。

条件处理方式
硬门通过接受本地结果。
结构/tool 确定性失败若通道允许且 DLP/预算通过，调用选定云 provider 一次。
DLP、安全策略或禁云阻断出云并返回稳定错误。
仅启发式高分记录 shadow decision，不改变当前结果。
高风险工具返回 tool call，由 LobsterAI 自行授权；Gateway 不声称知道授权结果。
调用上限：单请求最多“本地一次 + 选定云 provider 一次”，传输自动重试为 0。没有 Idempotency-Key 时明确为 at-least-once。

7. Trace、反馈与规则学习

Trace

每个 HTTP 请求创建 UUID trace_id。状态为 received、queued、leased、run_started、run_succeeded、response_started、response_closed；异常为 cancelled、failed、abandoned。默认只保存摘要与结构化元数据，正文显式开启；出云前执行独立 DLP。

反馈判定

来源可信度作用
显式 API + trace_id高保存反馈；有 passed verification 后才允许创建 V1.1 抽取任务
对话内肯定/否定文字不足V1 不自动绑定最近 trace，不触发规则
正向或负向语气低仅作为离线分析数据，不驱动生产路由

规则闭环

规则闭环后移到 V1.1。只有显式 trace_id、passed verification、稳定 scope_key、已脱敏且未命中敏感策略时，才可创建受限 DSL 候选。候选默认 pending，审批前显示冲突、证据、token 成本、影响范围和过期时间。

规则始终保留版本，回滚是创建 disabled 新版本，不删除历史。规范化 LearningPacket 后计算 packet_digest；同一 trace 与 digest 只允许一个有效抽取作业。审批前必须完成 lint、冲突检测和脱敏 fake fixture 回放，保存 evaluator evidence digest。注入 system context 前只加载已启用规则，最多 5 条、总 token 不超过 800，并声明规则不能覆盖安全策略、用户意图或工具权限。

MemoryIndex 兼容层

工程中新增 MemoryIndexAdapter 隔离 local、mem0 与未来 provider。Gateway DB 仍是规则审批、版本和回滚的权威源；外部 memory 只做相似经验检索和候选发现。mem0 结果必须带完整通道范围、剥离 memory 正文，只返回引用、分数、ID 与 metadata digest，再回查 Gateway DB 后才能注入。

Provider作用限制
localSQLite/FTS 本地索引，默认启用只读写脱敏摘要
mem0通过 metadata 做经验检索强制 channel filter，剥离 memory 正文并回查 Gateway DB
gbrainCapabilityUnsupportedAdapter无官方 API/repo/protocol 前默认 disabled，不发起外部调用
 
[memory_index]
provider = "local" # disabled | local | mem0 | gbrain (unsupported)
enabled = true
write_async = true
read_timeout_ms = 300
max_hits = 5

V1 的失败闭环仅使用脱敏 fake fixture 与 CI 回归夹具，覆盖 schema、SSE、DLP、预算、幂等、lease 和通道隔离；不得保存 production raw trace 或 provider raw response。

8. 并发、隔离与安全边界

  • HTTP 可并发进入；完整通道三元组使用有容量、有 deadline 的公平队列，超载返回 429 + Retry-After。
  • 初始 LOCAL_MODEL_CONCURRENCY=1，保证 Mac mini 上 omlx 行为稳定；云端单独限流。
  • V1 强制单 Gateway worker；SQLite 启用 WAL、foreign keys、busy timeout 和短事务，网络调用期间不持有事务。
  • 所有 trace、反馈和规则的读取都附带三元通道范围；不同 key 的查询返回 404，不泄露存在性。
  • 服务仅监听 127.0.0.1，所有请求仍要 Bearer key；管理接口额外要求本地 X-Admin-Key。
  • Trace 默认保留 30 天；后台清理任务删除过期数据。
真实边界：这只是同一台机器、同一 macOS 用户下的逻辑隔离。未来对外服务必须升级为独立 OS/容器或 VM、PostgreSQL、TLS、网络鉴权和分布式锁。

10. 第一版验收标准

  1. V1-A01 LobsterAI capture probe 明确所有 observed capability。
  2. V1-A02 omlx 文本、tool 与长响应 live baseline 完成。
  3. V1-A03 普通请求由 omlx 完成并形成 request trace。
  4. V1-A04 确定性结构失败最多升级一个云 provider 一次。
  5. V1-A05 Heartbeat 与最终 SSE 合同完整且不泄漏本地草稿。
  6. V1-A06 双 key 隔离且并发预算不超卖。
  7. V1-A07 幂等重放和冲突语义稳定。
  8. V1-A08 客户端断连传播取消并释放槽位。
  9. V1-A09 故障重启后 lease 可恢复且不重复云计费。
  10. V1-A10 敏感内容不出云/落盘，DB 前置故障 fail closed。
  11. V1-A11 P0 失败类别均有脱敏 fake fixture；安全扫描不含 key、Bearer、私钥或私有正文种子。

11. 后续演进：New API 与多实例

本地通路稳定后再前置 New API：Client -> New API -> Agent Gateway -> local/cloud providers。New API channel 必须关闭额外 fallback/retry，避免多层重试和重复计费；每个 Gateway channel 使用独立 token。

  • 先迁移 PostgreSQL，再运行多个 Gateway 实例。
  • 调度、预算、规则版本改为共享存储；必要时使用 Redis 队列和分布式锁。
  • Gateway 经 New API 调云模型时使用内部 service token 和真实模型名，绝不回调 agent-auto。
  • 增加 /v1/responses 与 /v1/messages，从而接入 Codex CLI、Claude Code、Kimi Code 等客户端。
  • 通过配置把 memory_index.provider 切换为 local 或 mem0；gbrain 在有官方协议前固定为 unsupported，外部不可用时降级到本地 DB。
  • MAGE 仅作为 V1.2+ 只读派生索引研究项，不进入 prompt 或路由；SkillDisCo/PFSM 不进入 API、schema 或验收。
  • 积累并人工抽检成功/失败 trace 后，再启动离线小模型微调实验。
