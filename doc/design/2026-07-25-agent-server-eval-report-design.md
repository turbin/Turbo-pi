# Agent-Server E4：总评估报告设计（replay 机制成败判定）

日期：2026-07-25
关联：`doc/design/2026-07-24-agent-server-eval-benchmark-tasks.md`（成功判据预注册）；`doc/design/2026-07-25-agent-server-tb-smoke-case-design.md`（用例设计）
用途：固定最终评估的数据口径、报告结构与判定规则——**报告格式先于数据产生，防止按结果改判据**。

---

## 1. 判定对象

"replay 机制"= agent-server 的经验回放闭环：session 落盘 → 离线进化蒸馏（ABILITY）→ 注入后续请求。本评估回答：**这套机制对真实 agent 任务表现是否有效**。

## 2. 数据来源（三层证据）

| 层 | 数据 | 产出阶段 |
|---|---|---|
| L1 benchmark A/B | TB 89 / SWE-bench Lite 子集：控制臂（直连）vs 实验臂（经 8789 注入）通过率、成本、失败分类 | E2/E3 |
| L2 飞轮实验 | 实验臂第 1 轮（冷库）→ 对评估库 `runDailyEvolution` → 第 2 轮（热库，注入第 1 轮经验）；同任务集通过率轮间对比 | E4 |
| L3 生产观察 | 周报 sidecar 的 4 周趋势（自然产量/截断/并存行/quality 分布） | 观察期（已在跑） |

L1 回答"注入有害吗"，L2 回答"经验飞轮转动吗"，L3 回答"真实使用中长期趋势健康吗"。三者都进总报告，权重 L2 > L1 > L3。

## 3. 指标定义（固定口径）

| 指标 | 定义 | 口径备注 |
|---|---|---|
| 通过率 | `is_resolved` 任务数 / 总任务数（tb pytest 判分 / swebench resolved） | 主指标；两臂同任务集同种子 |
| harness 故障率 | 0-token 或 parse_error 的 trial 占比 | **不计入任务失败**，单独列出（验收判例） |
| 轮间 delta | 第 2 轮通过率 − 第 1 轮通过率（仅实验臂） | 飞轮核心证据 |
| 注入命中明细 | 实验臂请求中 `experience_injection.retrieved` 非空的占比；被注入条目的 type/role/quality 分布 | 证明"注入确实发生了且内容相关"，空注入的 A/B 无意义 |
| 成本 | 每任务 total tokens（API 侧）、每轮总耗时 | 参考指标（轨迹方差大），只报不判 |
| 失败分类 | 模型能力 / 注入干扰 / 环境问题 三类（抽看轨迹归类） | 每臂至少抽 3 条失败轨迹 |

## 4. 判定规则（预注册）

| 结论 | 条件 |
|---|---|
| **成功** | 判据 ①②③ 全满足：实验臂通过率 ≥ 对照臂；第 2 轮 > 第 1 轮（差值 > 0，非噪声级 ±1 任务）；成本无数量级恶化 |
| **部分成功** | ①③ 满足但 ② 不成立（注入无害但飞轮未证）→ 转"注入检索 miss 还是经验质量不足"归因分析（FTS 命中抽查） |
| **失败** | ①不成立（实验臂显著劣于对照臂，差值 > 噪声级）→ 注入有害，立项查注入内容相关性 |

噪声级界定：5 任务冒烟 ±1 任务为噪声；89 任务 ±3% 通过率、SWE 10 实例 ±1 实例为噪声。超过噪声级才算差值成立。

## 5. 报告模板（E4 产出时逐节填写）

```markdown
# Agent-Server 经验回放机制总评估报告（<date>）

## 1. 结论（成功 / 部分成功 / 失败 + 一句话依据）
## 2. 数据总表
   | 臂/轮 | 任务集 | 通过率 | harness 故障率 | 注入命中率 | 总 tokens | 耗时 |
## 3. 判据逐条核对（①②③，各给数据与判定）
## 4. 飞轮实验明细（第 1 轮 → 进化产物清单 → 第 2 轮；注入条目实例 3 条全文）
## 5. 失败分类与典型轨迹（两臂各 ≥3 条）
## 6. 生产观察 4 周趋势对照（L3）
## 7. 归因与下一步立项建议
## 8. 附录：复现命令（双臂 tb/swe 完整命令行、评估库备份位置）
```
