# 下一步开发路线图：轨迹记忆驱动的本地 Agent 自进化系统

日期：2026-07-31
依据：用户设计意图（目标=学教师推理与轨迹增强本地 Agent+小模型；约束=①不微调只外挂记忆 ②harness 自进化 ③质量门控→云端→学习→持续进化 ④相似轨迹判断合并）
现状基础：学生-老师链路已接回（门控实证有效）、经验卡片库+FTS+注入在生产、进化管线离线就绪、三腿评估设施、9 篇论文已解析（`doc/research/papers/`）

## 1. 设计意图 → 现状映射（差距分析）

| 用户约束 | 现状 | 差距 |
|---|---|---|
| ①不微调，外挂轨迹记忆 | ✅ 经验卡片库（SKILL/SOP/ABILITY/EVIDENCE）+ FTS 检索 + 注入，零微调 | 卡片质量未实证（E5 飞轮未跑）；**无入库前验证** |
| ②harness 自进化 | ❌ harness 全静态（prompt 模板/注入上限/门控参数硬编码） | **全新能力**：需 harness 配置版本化 + 失败证据驱动的自动调优 + 人工审批门 |
| ③门控→云端→学习→进化 | 🟡 门控与云端兜底已实证（74% 升级全兜住）；escalation 全量落 `model_runs` | **断链**：gateway 的 escalation 轨迹未接入 evolution 管线（evolution 只读 agent-server session 目录）——"云端兜底的经验"没有回流学习 |
| ④相似轨迹判断合并 | ❌ 仅 contentHash 精确去重 | 无语义聚类/合并，卡片库必然碎片化（SKILL-DISCO 实测：不聚类 110 张 vs 聚类 5 张） |

**北极星指标（建议）**：升级率随时间下降（学生独立通过率上升）+ 任务 SR 上升 + 云成本/任务下降。当前基线：升级率 74%（gemma-12B）、ALFWorld SR 6.0%。

## 3. 路线图（R0→R4，依赖序）

### R0：评估收口与基线确认（1-2 天）【前置一切】
1. 三腿对照报告（L1 9/134 / L2 / L3 已完成，按 model×harness 配置呈现：SR/升级率/成本/失败分类）
2. **E5 飞轮实证**：L3 第 1 轮（冷库）→ runDailyEvolution → 第 2 轮（热库）→ 判据②（轮2>轮1）首次裁决
3. S1/S1b 学生修复选型（27B 换型 3 局 bisect vs `>`→`Action:` 协议适配）——修掉 74% 升级率的混杂变量，否则后续所有进化指标被 harness 缺陷污染（Harness-Bench 纪律）
- 验收：三腿报告 + 飞轮裁决 + 学生基线升级率 <30%

### R1：相似轨迹合并与记忆巩固（约束④，~3 天）
1. **卡片聚类合并**：embedding（或控制流特征）聚类 + 同类卡合并（保留最高 quality + 合并证据计数）；SKILL-DISCO 的 PFSM 子图思想作为过程性 SOP 的合并判据
2. **入库前验证**：新卡 active 前在 held-out 历史任务上回放验证（SKILL-DISCO 编译验证的轻量版），不过则 dormant——与既有 verifier≥0.5 串联为双门
3. 卡片库健康度指标：总数/去重率/注入命中率（复用 O 可观测基建）
- 验收：合并后卡片数收敛（目标去重率 ≥50%）；注入命中率不下降；169+254 测试全绿

### R2：升级轨迹学习闭环（约束③，~4 天）【核心价值回路】
1. **escalation 回流**：gateway `model_runs(purpose=escalation)` 关联的完整问答对 → 脱敏导出 → 作为 evolution 管线的专用输入流（区别于普通 session）——"教师修正集"
2. **失败模式蒸馏**：以"本地失败响应 vs 云端正确响应"对为单位提炼**修正型卡片**（"当 X 类任务/失败模式 → 应做 Y"），注入时对学生优先命中
3. **进化度量**：升级率按周追踪（weekly-report 已有骨架）；置信路由调研落地（COPE 式，门控从四类硬证据扩展）
- 验收：升级轨迹全量回流（零丢失）；修正卡在后续任务命中可观测（request_traces）；两轮进化后升级率可测下降

### R3：harness 自进化（约束②，~5 天，需用户评审门禁）
1. **harness 配置版本化**：prompt 模板/注入上限/门控阈值/检索参数从代码外提为版本化配置（当前值固化为 v1）
2. **失败批次锚定 + 自动 A/B**：周期性用失败轨迹批次驱动配置候选（保守搜索空间，MOSS 思路但**禁止自动改源代码**）；候选经 benchmark 回放验证
3. **人工审批门 + 一键回滚**：配置启用/回滚人工批准（V1-R09 与 MOSS 用户同意门一致）；全程审计（rule_hits 式记录）
4. 远期（另行立项）：MOSS 式源码级进化的 Go Gate
- 验收：一次完整的"失败批次→候选→回放→审批→启用→指标改善"闭环；回滚演练

### R4：学生成色与全本地化选项（R2/R3 后评估，~2 天）
1. 27B 学生正式评估（若 R0 未做）；置信路由上线效果
2. 决策点：升级率 <20% 且 SR 达标 → 评估老师退出数据面（零外泄模式）
- 验收：学生成色评估报告 + Go/No-Go

## 4. 执行顺序与并行性

```
R0（评估收口+学生修复）──必先做，否则指标被污染
 ├─ R1（轨迹合并）──────可与 R2 并行（不同子系统）
 └─ R2（升级学习闭环）──核心价值回路，R0 后即启动
      └─ R3（harness 自进化）──依赖 R1/R2 的记忆与度量基建
           └─ R4（全本地化决策点）
```

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 飞轮判据②不成立（注入无效） | R0 即暴露；按 E4 预注册路径分析（检索 miss vs 卡片质量），R1 的合并+验证正是对症修复 |
| 卡片库污染（错误经验被学习） | R1 入库验证双门 + Guard 卡只来自验证通过轨迹（既有 C 决策） |

| 27B 换型后仍有格式失效 | S1b prompt 适配兜底；R3 的 harness 进化可长期消化此类适配 |
