最终目标仍沿用 C 阶段： 学生模型在办公自动化域经教师少量指导及经验沉淀后逐步独立。

Q3 9B Agent trajectory 是否随经验积累改善 MAX_TURNS 触顶率、有效回合、 重复 Tool、错误重试、State revisit、 Memory hit 后的轨迹变化 有效学习应体现为： score ↑、cap rate ↓、重复行为 ↓。

3. Analysis Addendum：质量与独立性联合判定

3.1 防止“低升级率 = 假独立”

Pilot 已出现： 

canonical_dsl_scripts
score      = 0.06
round      = 30
escalation = 0

因此单独使用 escalation rate 无法区分“学生已独立”与“quality gate 漏升级”。

新增以下报告指标：

AutonomousSuccessRate = 成功且未升级任务数 / 全部任务数
MissedEscalationRate = 明显失败且未升级任务数 / 明显失败任务数
EscalatedSuccessRate = 升级后成功任务数 / 升级任务数

“明显失败”用于 retrospective analysis， 可由以下信号组合定义：

  • Judge score 低于预定义分析阈值；
  • 任务硬失败；
  • MAX_TURNS 触顶且目标未完成；
  • 连续 validation failure；
  • 核心交付物缺失。

最终独立性解释必须满足：

低升级率 + 足够质量 + 低漏升级率 ⇒ 可解释为学生独立性增强

4.4 D2 的角色重新定义

因冻结库 = D1 夜间 evolution 后快照， 而 D2 current library 在 D2 起跑时与其相同：

Library(current,D2) = Library(frozen,D1-post)

因此 D2 不用于估计真正的 Library Evolution Effect， 而定义为：

  • 2×2 zero-difference calibration；
  • 冻结 / 当前实例一致性检查；
  • Injection early-effect 检查；
  • 四臂执行与隔离机制校验。

D2 预期：

X2 − X1 ≈ 0
X3 − X4 ≈ 0

4.5 D7 才承担库演进主比较

D7 时：

Frozen = D1-post library
Current = D1～D6 evolution 后 library

因此 D7 用于估计实际 Library Evolution Effect。

5. 2×2 因果分析口径

5.1 Library evolution effect，在 Injection ON 条件下

E_library|on = X2 − X1

5.2 Library evolution effect，在 Injection OFF 条件下

E_library|off = X3 − X4

若 library 只能通过 injection 影响 Agent，则理论上：

X3 − X4 ≈ 0

5.3 Injection effect，在 Frozen library 下

E_inject|frozen = X1 − X4

5.4 Injection effect，在 Current library 下

E_inject|current = X2 − X3

5.5 Interaction Effect

Interaction = (X2 − X3) − (X1 − X4)

该指标用于回答：

随着经验库质量演进， 同样的注入机制是否变得越来越有价值？

如果 D7 出现： 

X1 − X4 = +0.05
X2 − X3 = +0.20

则说明主要提升不只是“有 Memory 就好”， 而是 Current Library 的经验质量已经发生了实质改善。

6. D1 / D7 差分与 DiD

原始判据③继续使用：

RawMemoryGap_D7 = Experiment_D7 − Control_D7

同时新增 Difference-in-Differences：

DiD = (Experiment_D7 − Control_D7) − (Experiment_D1 − Control_D1)

D1 在空库条件下可作为两个 arm 初始差异参照。

最终报告同时呈现：

  • Raw D7 Gap；
  • D1 Baseline Gap；
  • DiD；
  • task-level paired difference distribution。

7. Replay Gain 与 Transfer Gain 分离

7.1 Replay Gain

20 个重复任务每天都会重新出现， 因而其提升主要验证：

Student 是否能够从过去同任务 / 高度相似任务经验中正确检索并复用轨迹。
ReplayGain = Score(repeated, memory-on) − Score(repeated, memory-off)

7.2 Transfer Gain

为避免把 exact-task memorization 解释成一般能力提升， 增加少量 held-out transfer tasks。

要求：

  • 任务在 D1～D6 不进入 evolution；
  • 没有 exact trajectory 存在于 Memory；
  • 但任务类型与已有经验具有语义 / 工作流相关性；
  • D7 比较 memory ON / OFF。
TransferGain = Score(unseen, memory-on) − Score(unseen, memory-off)

Replay Gain 与 Transfer Gain 分开报告， 不混为单一“模型能力提升”。

8. Agent Trajectory 分析

8.1 MAX_TURNS 保持 30 不变

不提高 MAX_TURNS。 30 继续作为统一 Agent trajectory budget， 避免通过增加运行时间制造虚假改善。

“触顶”严格定义为：

CapHit = termination_reason == max_turns

不简单以 requests == 30 替代。

8.2 主要 trajectory 指标

指标 定义 / 用途
RoundCount 任务完成前实际 Agent 决策回合数
CapRate MAX_TURNS 触顶任务比例
RepeatToolRate 重复或近重复 Tool Call / 全部 Tool Call
RetryRate 错误后重复执行同类动作的频率
StateRevisitRate Agent 再次进入近似历史状态的比例
ProductiveRoundRatio 对任务完成产生新增状态推进的回合 / 总回合
RoundsToFirstUsefulMemoryHit 首次出现有效经验检索所需回合数
PostHitEfficiency 有效 Memory Hit 之后的完成效率

8.3 目标行为模式

若 Teacher → Memory → Student 机制有效，应同时观察：

Score ↑
CapRate ↓
RepeatToolRate ↓
ProductiveRoundRatio ↑
AutonomousSuccessRate ↑
EscalationRate ↓

仅“升级率下降”或“round 下降”不能单独判定学习有效。

11. 环境隔离与 side-effect 控制

四臂实验不仅要保证相同 task / seed， 还必须保证相同初始环境状态：

InitialState_X1 = InitialState_X2 = InitialState_X3 = InitialState_X4

对会产生真实写操作的任务：

  • workspace create/update；
  • workflow mutation；
  • DSL 修改；
  • 文件生成 / 更新；
  • 其他持久化 side effect；

四臂必须使用： 

Base Environment Snapshot
          ↓
    deterministic clone
          ↓
 ┌────────┬────────┬────────┬────────┐
 │        │        │        │        │
X1       X2       X3       X4

若无法实现 clone， 则必须在每个 arm 前进行 deterministic reset， 并通过 preflight checklist 验证。

12. 交叉日执行与时间漂移控制

按 Pilot 均值：

92 tasks × 16.5 min ≈ 25.3 h

因此 D2 / D7 是 logical experiment day， 不等价于自然日。

12.1 Snapshot Lock

四臂开始前固定：

  • Frozen library snapshot；
  • Current library snapshot；
  • 模型版本；
  • prompt / tool schema；
  • judge model；
  • environment base snapshot。

四臂完成之前：

禁止 hot-library swap

四臂全部完成后再进行当日 evolution。

12.2 Arm Order

不建议： 

全部 X1
→ 全部 X2
→ 全部 X3
→ 全部 X4

推荐以 task 为 block， 按 seed 确定性随机化 arm 顺序： 

task_01: X2 → X4 → X1 → X3
task_02: X3 → X1 → X4 → X2
task_03: X1 → X2 → X3 → X4
...

以降低 25 小时运行窗口内的时间漂移影响。

20. 风险登记

风险 级别 缓解措施
D2 Current 与 Frozen 实际同库， 导致 evolution effect 不可识别 P0 D2 改定位为 zero-difference calibration； D7 承担真实 evolution effect。
低升级率其实来自 quality gate 漏检 P0 同报 Autonomous Success / Missed Escalation / Escalated Success。
四臂共享环境导致 side-effect contamination P0 独立环境 snapshot / deterministic reset。
Evaluation arm trajectory 污染 future Memory P0 source_arm + eligible_for_evolution； 默认仅主 learning arm 可写入。
原始判据允许低质量系统全部 PASS P0 保留原判据， 但在最终决策中增加 Quality / Autonomy 二维 guardrail。
exact task replay 被误解释为泛化 P1 Replay Gain 与 Transfer Gain 分开， 增加 held-out transfer tasks。
30-round 指标过粗 P1 增加 RepeatTool / StateRevisit / ProductiveRound 等 trajectory 指标。
Teacher / Judge 同源 P1 D2 / D7 小样本独立 audit。
四臂运行 >24h 引入时间漂移 P1 snapshot lock + task-block randomized arm order。
Memory 检索错误造成反向迁移 P1 记录 similarity / reuse-adapt-reject / outcome-after-hit， 支持错误归因和降权。
n=20 被误解释为足够统计功效 P2 仅声明与 C 保持相同样本规模和粒度， 不做显著性宣传。

若以上指标形成一致方向， 才能够较有力地支持以下结论：

Qwen3.5-9B 的基础规划能力虽然弱于大模型， 但通过教师产生的成功经验进行外部化、 演进、状态感知检索与轨迹适配， 可以减少自身实时规划负担和无效 Agent 循环， 从而以较低推理成本获得更高的任务完成质量与自主性。

这验证的不是“9B 参数能力已经等同 27B”， 而是：

SystemCapability(9B + Teacher Memory) > SystemCapability(9B Alone)

以及进一步需要验证：

CostAdjustedQuality(9B + Memory) ≈ or > CostAdjustedQuality(Large Model Agent)

22. 实验解释红线

  1. 不把 0/20 升级解释为统计证明真实升级率 <5%。
  2. 不把 D1～D7 的 20 个重复任务解释为 n=140。
  3. 不把 exact-task replay gain 自动解释为泛化能力。
  4. 不把 round 降低但 score 同时下降解释为 Agent 改善。
  5. 不把低 escalation 单独解释为学生独立。
  6. 不把 Teacher/Judge 同源下的单一评分结果解释为完全客观能力提升。
  7. 不在看到结果后修改原始①～⑤主判据。
  8. 不允许 Evaluation arm 静默污染未来生产 Memory。
  9. 不在四臂执行中途替换 Current Library snapshot。
  10. 不通过提高 MAX_TURNS 来制造“成功率改善”。
