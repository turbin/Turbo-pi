## 第 0 层：一页大白话总结（给非技术读者）

**我们做了什么**：让一个小模型（9B）连续 7 天做同一批办公任务，每晚把当天的经验整理成"笔记卡片"存起来，第二天翻着笔记干活。想验证：记笔记能不能让笨模型越干越好。

**最终答案（修正后）：按现在这套记法，记忆系统未展现出可重复的平均正向增益，并在少数任务上诱发灾难性翻车。**

- 不能得出"记忆系统平均降低表现"的强结论；更准确的表述是：**当前这套记忆系统（只攒不管 + bm25 检索 + 强遵循注入）无正增益，且存在尾部灾难风险。**

- 最后一天对照考试：翻 6 天攒的 842 张笔记考 **0.268**，翻第 1 天的 235 张旧笔记考 0.446，不翻笔记考 0.445/0.434。差距 −0.177，统计检验 p=0.043（卡边）。
- **但要诚实**：这个"显著为负"主要由**少数几道 0 分题**驱动——重复集 5 道 0 分（4 道时间耗尽没交卷、1 道交了卷但被 hybrid 罚则清零）；按预注册敏感性规则剔除最极端的 3 道后，差距缩到 −0.072 且不显著（p=0.309）。因此不能得出"记忆系统平均降低表现"的强结论；可确证的结论只有：**当前这套记忆系统无正增益，并在少数任务上诱发灾难性失败**。
- 翻车方式有逐题实证（个案级，致害率未知）：①**"解题攻略卡"**——把某题上次的做法蒸成步骤攻略，9B 死照执行，连攻略里多带的、题目没要求的步骤也照做，掉进修脚本死循环，时间耗尽没交卷；②**"碎碎念卡"**——模型的自言自语片段被当经验存了几十到上百张，被注入到不相干的题里。
- 另一个重要发现：老师模型能解的难题，**把老师写的标准攻略直接喂给 9B 也救不了**（照样 0 分）——甚至有一道题 9B 裸考 0.80、喂了攻略反而 0 分。说明“注入东西”这个动作本身就能干扰它；难题上还观察到一例执行瓶颈（拿完整攻略跑满回合也没完工）。
- 实验质量经得起查：主检验数字经独立复算一致、外援裁判两次抽查打分公道、8 道保密题零泄漏、对照组零污染。两次事故（磁盘爆、裁判没钱）有记录有修复无数据污染。

**一句话（修正后）**：当前这套记忆系统不修不能带进 ALFWorld——不是因为它"平均变差"，而是因为它不能提供可靠增益，且会在尾部任务上造成严重失败；修法与验证功效分析完成前，ALFWorld 应继续阻塞。

- **现象**：2026-08-25 夜晚 campaign 进程因磁盘满 OOM；日志路径 `var/log/agent-server/...` 已启用轮转。

### issue-023：裁判 402 挂起

- **现象**：judge API（deepseek-v4-pro）因账户余额不足返回 402，原始重试逻辑退避时间无封顶，导致任务挂起约 10 小时。
